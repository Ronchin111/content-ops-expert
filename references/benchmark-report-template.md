# 对标爆款报告：PDF 模板架构

## 2026-11-22｜新版作品评价与拆解

新报告以 `work_evaluation` 字段启用本结构。作品数据、评论原文、账号简介、逐段引文、画面观察和原片截图沿用已有字段。Markdown 和 PDF 按同一顺序生成，章节按内容分页。

| 章节 | 新填字段与呈现 |
|---|---|
| 01 作品评价 | `work_evaluation.metrics_assessment` 评价实取计数，`comment_pattern` 写样本共性，`comment_appeal` 解释获赞较多的评论可能为何共鸣，`overall` 给整体判断和证据限制。 |
| 02 账号人设 | `account.positioning` 写简介与出镜角色，`account.work_fit` 写作品对人设的作用。 |
| 03 脚本 | `script_analysis.topic_assessment`、`platform_fit` 和可选 `platform_sources`（`label`、`url`），接原推进线、时间轴和结构分析。引文差异可放分段的 `evidence_note`。 |
| 04 画面 | 在 `visual_analysis` 中补 `composition`、`lighting`、`background_and_props`，与已有字幕、图形、画面变化和 `frame_evidence` 共同呈现。每张截图及其拍法保持在同一页。 |
| 05 成功要点与可借鉴打法 | `conclusion.success_assessment` 写有依据的传播解释，`account`、`script`、`visual` 分别提炼可用做法。可选 `conditions`、`risks`。结尾 `next_action.prompt` 只邀用户提供现有脚本，`deliverable` 说明输出口播稿和逐段拍法。 |

下面保留旧 JSON 的模板说明和渲染兼容性。

2026-11-15。本文件定义「对标爆款拆解」PDF 模板的完整架构。模板职责：**接收分析结果 JSON → 排版成 PDF**。分析逻辑由主 Agent 完成，分析结果填入 JSON 后传给模板。模板不判断、不解释、不算数据。

本模板独立于自有作品四页复盘模板 `report-template-architecture.md`，不共用其导航、字段或渲染器。对标分支单独建渲染脚本，不动 `build_report_pdf.py`。

---

## 一、总体原则

### 这份报告回答什么

读完这份报告，用户应该能说出三件事：

1. 这条片子做对了什么（结构、画面、钩子——具体到哪一句、哪一格）
2. 这套做法能不能搬到我自己身上（能留什么、必须换什么、需要什么条件）
3. 下一步做什么（改写、仿写、还是诊断）

### 输入格式

模板接收一个 JSON 文件（路径由命令行参数传入）。下文第四章定义完整数据模型。

## 二、每页结构

### 所有页面共用元素

**顶部信息栏**（每页第一行）：

```
对标爆款拆解  ·  {平台}  ·  {作者名}  ·  {时长}  ·  {采集日期}
```

字体：9pt，灰色。下方一条细线分隔。

**页脚**（每页底部）：

```
左侧：多平台内容运营专家 · 对标爆款拆解
右侧：第 N 页 / 共 3 页
```

字体：8pt，灰色。

---

### 第 1 页：作品概览

**1.1 基本信息**

视频标题（完整原文，含话题标签）、作者名、平台、时长、分辨率、作品链接（小字）、数据采集时间。

**1.2 账号信息**（能取多少写多少）

- 账号名称
- 简介（如有；未取到时写「页面未能读取」）
- 置顶作品标题（如有，最多 3 条；未取到时省略此行）

**1.3 公开数据**

四个计数并排显示（大号数字 + 单位标签）：

| 点赞 | 评论 | 收藏 | 分享 |
|---|---|---|---|
| 1.3万 | 2034 | 9071 | 2096 |

保留页面原始精度。未显示的指标不出现（不填 0）。

下方一行小字：采集时间、数据来源（公开页面可见值，不含播放量/留存/私信）。

**1.4 评论快照**

列出最多 3 条页面可见评论。每条格式：

> 「评论原文」
> —— 赞数 · 日期 · 属地（如有）

下方一段话概括这些评论集中在问什么（价格 / 效果 / 门槛 / 资源……），注明样本范围（首屏可见 N 条，不是全部评论）。

---

### 第 2 页：脚本结构

**2.1 结构总览**

一条横向流程图（箭头连接），概括本片的推进线。每个节点一个短语，对应一段的功能。示例：

```
圈人 → 排除选项 → 给唯一答案 → 拆掉门槛 → 讲机制 → 收口
```

流程图下方一句话说明总时长和各段占比。

**2.2 逐段拆解**

每段一个条目，包含：

- **时间区间**（秒）
- **关键台词**（原文引用，注明来源：画面字幕 / 机器稿）
- **这一段在干什么**（一句话功能描述）
- **承接**：前一段留下的问题 → 这一段怎样接 → 留给下一段什么
- **画面**（这一段的画面特征——真人口播 / 图形卡片 / 素材插入）

如果机器稿与画面字幕不一致，两种写法并列，不合成一份。

**2.3 值得学的地方**

2—3 条具体判断，每条带原句和时间。格式：

> 第 X 段「原句」起了什么作用 → 为什么有效 → 在你的账号里可以怎样用

---

### 第 3 页：画面分析 + 可借鉴骨架 + 行动选择

**3.1 画面逐项记录**

| 观察项 | 记录 |
|---|---|
| 人物与场景 | 一个人/多人、室内/室外、背景活动 |
| 字幕样式 | 位置、颜色、描边、大致字号 |
| 抬头标题 | 有无、文字内容、位置、样式 |
| 非真人元素 | 卡片、流程图、弹框、图标——在哪些秒出现 |
| 画面变化 | N 张截图中，哪些时间点发生了明显的视觉切换 |
| 字体动画 | 截图间字幕是否发生了变化（逐字出现 / 弹入 / 颜色变化——仅描述可见差异，不判断动画类型） |

约束：所有描述限「在已检查的 N 张截图中」，不写「全片始终」。字体只写视觉特征，不写精确字体名。

**3.2 可借鉴骨架**

从本条归纳的结构步骤（步骤数量由实际内容决定），配：

- **可替换变量**：列表，每行「原作者用 X → 你可以换成 Y」
- **适用条件**：用这套结构需要哪些前提（有真实经历、有对应素材、有明确受众……）
- **失败风险**：最容易翻车的地方（承诺过大、缺少证据、结构模仿但内容空洞……）

**3.3 你的下一步**

三个选项，一行一个：

1. 按这套结构改写现有脚本
2. 用这套结构仿写新脚本（选题 + 目的 + 素材）
3. 用这套结构诊断已有作品

每个选项附一句话说明用户需要提供什么。选项本身不带勾选框或交互——用户在会话里回复选择。

## 三、语言与排版规范

### 引用标注

- 画面字幕引用：`「原句」（画面字幕，X.X秒）`
- 机器稿引用：`「原句」（机器稿，X.X秒）`
- 评论引用：`「原文」—— 赞数 · 日期`

### 禁用词

同自有作品模板 `report-template-architecture.md` 第三章语言规范（禁用词表、句子规则、称呼规则），对标模板同样执行。新增一条对标专用约束：

- 不出现「爆款」「爆了」等效果断言词作为事实判断——标题里引用用户的说法除外
- 如果用户自己说「这是一条爆款」，正文写成「用户指定的对标作品」，不在正文中反复使用该词

### 排版

- 页面：A4 竖版
- 字体：中文无衬线体（微软雅黑 / 思源黑体），西文按系统默认
- 正文 10pt，标题 14pt / 12pt，小字 8pt
- 表格式对齐：左对齐文本，右对齐数字
- 流程图用简单箭头字符（→），不依赖图标字体

- `optional` 标记的字段缺失时渲染器跳过，不报错
- 所有时间码和原文引用由 Codex 核对后再进 JSON，不在模板内做二次校验

## 五、渲染器接口

当拆解包含画面证据时，成稿 JSON 的 `visual_analysis.frame_evidence` 填入对应的关键截图，最多八张。每张包含 `file`（报告目录内相对图片路径）、`time_seconds`（截图实际秒数）、`title`、`observation`（截图看得到什么）和 `filming_tip`（用户可以照做的一条拍摄动作）。把相应 JPG 或 PNG 放在报告目录内的素材子目录。PDF 在正文后每页嵌入最多两张，Markdown 以相对路径显示相同图片。没有截图的历史 JSON 可按原格式渲染。

对标专用渲染脚本（文件名待建，如 `scripts/build_benchmark_pdf.py`）：

- 输入：一个 JSON 文件路径（命令行参数）
- 输出：JSON 同目录下的 `对标爆款拆解.pdf` 和 `对标爆款拆解.md`
- 退出码：0 成功 / 非 0 失败（含失败原因输出到 stderr）
- 不修改旧渲染器、旧模板、wording() 或禁用词表
- 遇缺失字段按本节约束降级渲染，不以字段不全为由拒绝整个 PDF
