# 自有作品复盘：连贯正文与分析补强

2026-11-23，负责人认可笔记本DSH转交PDF的行文风格，要求固化写法、结合已有知识库适当补强分析。四步职责、K01—K08及完整分析底稿保留；只替换新报告的卡片呈现与不足的推理。该文风不依赖DeepSeek API，实际成稿模型按本页执行。

## 怎样写得像这份样稿

当前固定采用05号重点标识版的分段和标注方式，语言遵守[轻专业写法](report-prose-layout.md)：日常、具体、顺口，分析要有依据。05号是排版参考，不代表其中每句话都已定稿；语言继续以负责人认可的本商品正文规范为参照，不能因补充分析而写回抽象术语。

先有一个能被原片支持的总判断，再讲值得保留什么、主要问题是什么、先做什么。每个主要问题用完整段落写：时间/原话/画面 → 这一段原本负责什么 → 实际给了什么、还缺什么 → 为什么这个差距影响本片目标 → 建议与取舍。不是给五张卡片加承接句。

学习样稿的具体对象、判断力度和解释顺序，不复制其绝对化措辞。比如“53—87秒在列三组工具分工”是观察；“若观众想了解用途，这段先要求他理解后台分工，却尚未说明如何用到眼前工作”是有理由的分析。两者都比“前置价值、加强证据”更能指导作者。

章节可按“总评与数据—账号人设—脚本与画面问题—下一步”组织；脚本与画面可以同章，画面集中说明，不重复拆章。小标题应带判断，正文自然分页，4～5页；不是一页一章。每个问题一至三段，建议段直接回答前面的缺口。每个分析单元用有信息的段首标识（如“问题一｜标题和首屏问的不是一件事”“保留｜本人近景”“①先备材料”），把重点判断局部加粗，完成标准可加下划线。长段在事实、判断或动作转换处拆开，通常每段2～4行；解释仍接在判断后，不拆成互不关联的卡片。不能把“连贯正文”误解为整页一种字重。

原片截图、数据条形图、功能时间线紧邻相关论证；不使用一组组独立边框卡片、空占位框、满页数字块和另页技术待办。允许首页一个简短总评框，以及正文分隔线、段首符号、加粗与少量下划线；这些是阅读层级，不等同于卡片化。图注说该图支持哪个判断。必要时用一张改动表，其他以连续段落为主。优先删重复，不删解释，不缩字号塞页。

固定标注用法：

- 首页总评框分行写“结论、保留、先改、第一动作”，只用一个总评框。
- 章标题下有分隔线；段首先说具体内容，如“问题一｜标题和首屏问的不是一件事”“■ 保留｜本人近景”，不要只写空泛的“分析”“建议”。
- 每个分析小节把最重要的一句或一小段加粗，解释保持普通字重。只看标题和粗体，应能找到主要问题与改法；不要整段全部加粗。
- “→ 拍法/改法”带出具体动作；“①②③”表示先后步骤。符号前后一致，不为装饰不断更换。
- 完成标准可加下划线；数据来源和补充说明用较小的说明字。长段在意思转换处拆开，通常每段2～4行，原因解释仍紧跟判断。
- 标题、动作和紧随的解释一起起排，不能把标题留在页尾。检查实际PDF，确认标识醒目、符号能显示，不能只检查输入里有没有写标记。

## 在已有方法上补强什么

- **K01受众与任务**：分别核标题叫谁进来、主要篇幅服务谁、已知账号目标是谁。区别“本片切口”和“账号定位”，不能因家长提问就把AI实战账号缩成家长/教培招生号。受众错位必须解释，不靠标签判断。
- **K02/K03选题与兑现**：先问这个观众为何在意，标题、首屏、开场是否承诺同一件事，再找正文兑现位置。先给答案不必然错，答案能否听懂、有何收益才是判断重点。原话难懂若来自机器误识，先核对，不用错词批评作者。
- **K04推进**：每段是否新增必要解释，移走后会丢什么。提前某案例时，要说明为何选它、它是否能代表主张、需要哪一句前提；不要所有作品都改成“一个案例前置”。保留结构化讲法的优点，层级可作解释工具。
- **K05主张和画面**：区分本人自述、可读产物、实际操作、前后结果。绿色提纲能帮助跟随结构，但未必足以证明定制或效果。静帧只判断该时刻，缺连续素材不判整片无实物/无动效；正常构图、亮度无需为了凑建议重拍。
- **K06/K08反馈与数字**：来源归属不可靠时先交代，不让它主导当前作品诊断。次数不换人数；不同口径不推连续队列，不用全片完播推某秒最多几人听到。无基准不写“正常/不离谱/最猛”，零关注不等于没信任；评论正文缺失不编共识。内容判断仍可明确，不用“值得检查”逃避分析。
- **K07迁移与行动**：提炼“为何这样安排”，而非复制本片名词。最多两三处优先调整，每处给原因、动作、所需材料及完成标准。先后顺序按依赖、影响和成本说明；试讲时长只是建议，不能冒称几秒一定说完。缺关键材料就指出它影响哪个决定，不用虚构示意填成已验证案例。

## 正文交接与生成

沿用`analysis_detail`事实/方法/发现/计划。新任务用`report_prose`代替`report_view`：

```
{"version":1,"summary":"总判断，随后解释依据和优先动作",
 "sections":[{"title":"有信息的标题","finding_refs":["A1"],
   "paragraphs":["**主要判断**，随后解释依据……"],
   "presentation":[{"at":0,"kind":"subhead","label":"问题一｜具体问题"}],
   "figures":[{"after":0,"kind":"frame","evidence_ref":"F01","caption":"这一帧说明什么"}]}]}
```

`presentation`可选：at为段落索引，kind为subhead/action/note，前两项需label。用于区分问题、保留点、动作和来源说明，label应表达具体信息，不只贴“分析/建议”。`**文字**`局部加粗，`__文字__`加下划线；总评用简短分行说明保留、先改和第一动作。章节标题须与后文同页起排，不能悬在页尾。扫读标识就应能找出问题和下一步，再读正文能理解理由。

图形可选`frame`（证据编号）、`metrics`（keys只取事实包已有指标）、`timeline`（沿底稿时间），`after`指段落从0起的位置。无必要不放图。首页元信息仍来自`video`，来源和限制集中放正文相关处。新任务不再要求五页卡片字段/卡片条数，旧`report_view`只兼容历史稿。

执行`review_analysis.py validate`后，由`build_report_pdf.py`直接生成正文PDF与同文Markdown。空正文、越界图片、虚构图形值应拒绝。字段与渲染检查不能证明分析有价值：另读正文，确认普通读者说得出主要问题、理由、第一步和完成标准；口播示范要能说出口。最后邀请用户提供下一条脚本，完整仿拍仍属后续。

## 样稿采用边界

来源是用户提供并认可文风的本商品正文规范；真实作品名称、原件和位置只保存在本机验收记录，不写入通用Skill或交付包。认可文风不等于接受其中所有统计推算、受众假设或“唯一/全部”判断。保留来源，不冒充API原答复。
